# 目录与解析器架构

本文记录 `watermark-go` 重构后的解析器边界。生产解析器是可审计、固定来源的应用组件，不是可在运行时下载或替换的插件。

## 目录边界

- `internal/parser/`：稳定的 Parser、Descriptor、Result、Registry、请求预算和短期会话材料契约。
- `internal/parser/native/`：固定提交迁移而来的 26 个 Go 平台适配器，以及脱敏合成 fixture。
- `internal/parser/universal/`：结构化 Python bridge 适配器。它不能直接启动进程，必须注入隔离 Runner 和已验证的本机 netguard proxy。
- `internal/parser/ytdlp/`：固定 yt-dlp 命令契约。它只生成受控 argv/env，并把执行委托给隔离 Runner。
- `internal/netguard/`：唯一的进程内 HTTP 出口，负责 typed URL、DNS 与实际 dial 绑定、每跳重定向复验、敏感 header 剥离、TLS 和响应限额。
- `bridges/universal/python/`：固定来源的 helper 输入。Task 4 完成 sandbox/proxy handshake 前，production 中保持 fail-closed。
- `internal/httpapi/`：当前兼容 API、后台 API、请求中间件和服务启动保护；平台目录、展示名、域名和 ID 能力均读取 Registry snapshot，不保留第二份映射。
- `internal/admin/`：后台认证、审计、单机汇总和基线执行，不承担开放解析路由。

## Descriptor registry

每个平台由一个不可变 Descriptor 描述：

- 稳定 ASCII `PlatformKey`、展示名和兼容 alias；
- exact host 或显式允许子域的 `HostRule`；
- video、gallery、audio、live-photo 等 capability；
- 确定性 priority、允许的 query key、ID 支持；
- 单次 Parse 共用的请求和重定向预算；
- 零 I/O constructor。

`internal/parser/native/testdata/catalog.golden.json` 精确锁定 26 个 key、41 条 host rule、21 个 ID adapter 及逐项 metadata。Registry 构造时拒绝重复 key/alias、跨平台重叠域名和重复 query policy。`redbook → xiaohongshu`、`quanminkge → kgqq`、`xigua → ixigua` 仅在规范化层兼容，catalog 的稳定主键不变。

路由判定同样只读取这份 registry：httpapi/admin 不得用展示名、URL path/query 的字符串包含关系或第二份 host map 猜测平台。未知 host 必须返回稳定的 typed error；允许保留的 query key 经大小写与百分号解码归一、去重和确定性排序后，其余字段（包括 tracking 参数）全部移除。

Registry 的结构借鉴了 `ucmao/media-parser` 的集中注册与富媒体表达思路，但没有复制其源码，也没有把其候选域名静默加入生产。研究结论、固定 provenance 和采用/不采用项见 `docs/research/media-parser-review.md`。

## 单次解析与富媒体结果

每次 `Parse(ctx, request)` 只创建一次上游 snapshot。短链、页面和 API 可以在 Descriptor 总预算内组成多阶段 snapshot，但不同 getter 不得重复抓取同一 URL。所有请求共享取消、总时限、请求次数、重定向次数和 duplicate-fetch gate。

统一 Result 使用强类型字段：

- `ImageAsset{URL, LivePhotoURL}` 表达图集和 live photo；
- `MediaCandidate` 表达类型、质量、码率、尺寸和来源顺序；
- candidate 采用显式 metadata comparator；缺少 metadata 时保持 parser 原顺序；
- helper 的未知 `Raw map` 字段不会进入 API Result、日志或 evidence。

嵌入页面 JSON 使用转义和嵌套感知的提取器，不以 `.*?</script>` 假定 JSON 边界。Bilibili/快手的完整、转义、截断、字段换层、登录、风控、空核心字段和 INIT_STATE/Apollo 多载体行为由 `testdata/structured/` 的脱敏合成 fixture 锁定。

## 凭据与短期材料

解析器不得调用 `os.Getenv`、`os.LookupEnv` 或 `os.Environ`。微博/西瓜 Cookie 和搜狐 token 只能由 typed `Config` 注入；空 Cookie 不设置 header。搜狐 token 缺失时返回 `credential_required`，源码、错误和测试均不包含 token 原值。

`SessionMaterialProvider` 以 `platform key + exact normalized host` 为唯一 scope，具备 TTL、singleflight、LRU 硬容量和每次 Parse 最多一次 refresh。只有 typed `session_expired` 可触发失效；取消、超时、安全拒绝、schema 变化、缺少凭据和内部错误均不得刷新。

## Runner 与通用解析器

universal 和 yt-dlp 不得直接调用 `exec.Command*`，也不得继承父进程环境。结构化命令只能包含固定 binary/script/source/workdir、最小 env、唯一不可覆盖的 loopback proxy，以及 process-group termination 要求。

Task 4 提供经过 handshake 的 GuardProxy 和 network-isolated executor 前，两者的 constructor 必须返回错误，production fallback 保持 disabled。opaque music config 不进入 payload、argv、env、UDS、helper 日志或输出。

固定绝对路径本身不代表可信。Runner constructor 还必须获得 `ImagePathPolicy` capability，并分别验证 executable、script、read-only source 与 work-dir 均属于 Actions 构建的不可变镜像；任意宿主机路径、可写挂载或缺少 provenance policy 都必须 fail-closed。production 配置在 Task 4 隔离运行时接线完成前拒绝启用 universal/yt-dlp engine 或 fallback。

## 固定来源与发布边界

第三方 helper/source 的 repository、commit、tree 和许可证由 provenance 文档固定。生产运行时禁止：

- 从上游同步或自动更新解析器源码；
- 在后台写入可执行 tools、venv 或 parser 目录；
- 把宿主持久化目录挂载为可变 `/app/tools`；
- 由 API 进程启动未隔离 subprocess。

镜像只能由 GitHub Actions 基于已审查提交构建并推送到 GHCR，发布和回滚使用不可变 digest。当前服务器只允许拉取并部署该 digest，禁止在服务器上执行 Docker/Buildx 镜像构建。
