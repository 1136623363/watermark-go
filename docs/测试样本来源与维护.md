# 测试样本来源与维护

后台的“平台能力 / 测试样本”用于验证当前解析器在真实链接上的可用性。样本会进入数据库管理，默认目录只负责首次初始化和补充缺失平台。

## 样本分层

1. 核心样本：项目原生 Go 解析器覆盖的平台，通常用于首页一键测试。
2. videodl 扩展样本：来自 CharlesPikachu/videodl 支持平台或公开状态页，用于验证 `universal` 解析器的视频能力。
3. musicdl 扩展样本：来自 CharlesPikachu/musicdl README 或公开播放页，用于验证 `universal` 解析器的音乐能力。

## 启用规则

- 有 URL 的默认样本默认启用，便于后台动态统计样本数量。
- 没有公开可访问 URL 的平台保留空样本，不参与一键测试。
- 后台手动新增的样本以数据库为准，后续默认样本同步不会覆盖已有 URL、启用状态和备注。

## musicdl 注意事项

- `musicdl` 播放列表解析可能会逐首校验下载地址，耗时明显高于视频解析。
- 后端默认将 `musicdl` 单样本超时限制为 15 秒，单次最多读取 5 首，避免一个平台拖垮整轮测试。
- Apple Music、Deezer、Free Music Archive、TIDAL 等平台可能需要 cookie、token 或特定网络环境。可在后台“运行设置”中的 `musicdl 配置 JSON` 填写来源配置。
- 配置 JSON 推荐格式：

```json
{
  "sources": {
    "TIDALMusicClient": {
      "token": "your-token"
    }
  },
  "requests_overrides": {
    "headers": {
      "Cookie": "your-cookie"
    }
  }
}
```

## 维护建议

- 优先使用公开、短播放列表或单曲页作为样本。
- 不要使用成人内容、明显侵权内容、私有会员内容作为默认样本。
- 单个平台失败不等于后端主链路异常，需要结合错误信息、耗时、解析器名称和网络环境判断。
- 补充样本后，先在“测试样本”页面单测，再用“平台能力”做整轮测试。
