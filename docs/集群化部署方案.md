# 去水印后端集群化部署方案

本文档记录当前项目从单机部署演进到小型集群的方案。目标是在不推翻现有 Docker/Jenkins 流程的前提下，把闲置机器 `192.168.31.222` 纳入解析能力池，优先解决解析任务的横向扩展问题。

## 目标架构

第一阶段采用“主节点 + 解析工作节点”的轻量集群：

- 主节点：继续运行 Nginx、MySQL、Redis、后台管理系统和一个本地后端实例。
- 工作节点 `192.168.31.222`：只运行后端解析服务，不运行 MySQL、Redis、Nginx。
- Nginx：部署在主节点，对解析 API 进行负载均衡；后台管理、工具更新和运行设置接口固定转发到主节点后端。
- MySQL/Redis：仍由主节点统一提供，worker 通过局域网访问。
- Jenkins：一次推送后同时更新主节点和 worker 节点。

## 当前实施范围

本阶段实现以下内容：

- 新增 worker 专用 `docker-compose.prod.worker.yml`。
- 生产 Nginx upstream 支持环境变量注入，可直接加入 `192.168.31.222:5001`。
- 主节点 compose 保留单机默认值，同时允许 MySQL/Redis 绑定到局域网地址。
- 后端 `/api/health` 和后台摘要返回节点身份、角色、解析器状态与集群健康状态。
- Jenkinsfile 增加 worker 部署步骤，推送后自动部署新机器。

暂不实现以下内容：

- MySQL 主从、自动故障转移。
- Redis Sentinel 或 Redis Cluster。
- Keepalived/VIP。
- Kubernetes、Swarm、Consul 等复杂编排。
- 跨节点任务迁移和分布式锁重构。

## 节点分工

### 主节点

主节点仍然是控制面和数据面核心：

- 对外端口：`5001`。
- 本地后端容器：`watermark-backend`。
- Nginx 容器：`watermark-nginx`。
- MySQL 容器：`watermark-mysql`。
- Redis 容器：`watermark-redis`。
- 持久化目录：`/vol1/1000/Configs/watermark-backend`。

### Worker 节点

Worker 节点只负责解析：

- 地址：`192.168.31.222`。
- 用户：`root`。
- 服务端口：`5001`。
- 容器名：`watermark-backend-worker`。
- 部署目录：`/var/watermark-backend/app`。
- 持久化目录：`/var/watermark-backend/data`。

Worker 节点需要能够访问主节点的 MySQL `3306` 和 Redis `6379`。Jenkins 会把这两个端口绑定到 `GATEWAY_LAN_HOST` 指定的局域网 IP；建议再用服务器防火墙白名单限制来源为 `192.168.31.222`，不要暴露到公网。

## Jenkins 部署变量

Jenkinsfile 默认使用以下关键变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `REMOTE_HOST` | `host.docker.internal` | 主节点 SSH 地址 |
| `GATEWAY_LAN_HOST` | `192.168.31.11` | Worker 访问主节点数据库和缓存的局域网地址 |
| `WORKER_ENABLED` | `true` | 是否部署 worker |
| `WORKER_HOST` | `192.168.31.222` | Worker SSH 地址 |
| `WORKER_USER` | `root` | Worker SSH 用户 |
| `WORKER_DEPLOY_DIR` | `/var/watermark-backend/app` | Worker 部署目录 |
| `WORKER_PERSIST_ROOT` | `/var/watermark-backend/data` | Worker 持久化目录 |
| `WORKER_APP_PORT` | `5001` | Worker 服务端口 |

如果主节点局域网 IP 不是 `192.168.31.11`，需要在 Jenkinsfile 中调整 `GATEWAY_LAN_HOST`。

## SSH 要求

Jenkins 使用 `/var/jenkins_home/.ssh/id_ed25519` 连接主节点和 worker。不要把 root 密码写入仓库。

Worker 首次接入时，在 Jenkins 容器或 Jenkins 所在环境中执行一次公钥授权即可：

```bash
ssh-copy-id -i /var/jenkins_home/.ssh/id_ed25519.pub root@192.168.31.222
```

完成后 Jenkins 才能无密码部署 worker。

## Worker 目录与磁盘规划

`192.168.31.222` 已将 `/srv` 适当缩小，并把释放的 LVM 空间扩给 `/var`。当前规划为：

```text
/var/watermark-backend/app                 Jenkins 下发 compose 文件和 .env
/var/watermark-backend/data                Worker 持久化根目录
/var/watermark-backend/data/backend/cache  后端缓存
/var/watermark-backend/data/backend/logs   后端日志
/var/watermark-backend/data/backend/tmp    临时文件
/var/watermark-backend/data/tools          yt-dlp/videodl/musicdl 等热更新组件
```

Docker 默认仍使用 `/var/lib/docker`，现在 `/var` 已扩容到约 `194G`，足够承载 worker 镜像、容器层、日志、临时文件和工具更新目录。

## Nginx 分流

主节点 Nginx 使用 `WATERMARK_UPSTREAM_SERVERS` 注入 upstream，默认单机：

```nginx
server watermark-backend:5001 max_fails=3 fail_timeout=10s;
```

Jenkins 部署集群时会写入：

```nginx
server watermark-backend:5001 max_fails=3 fail_timeout=10s; server 192.168.31.222:5001 max_fails=3 fail_timeout=10s;
```

Nginx 使用 `least_conn`，更适合解析任务这种耗时不均的请求。

后台管理相关路径固定走主节点，避免登录态、工具更新、运行设置在不同 worker 之间漂移：

- `/admin`
- `/admin/api/`
- `/admin/api/tools`
- `/api/settings`

## 后台集群配置页面

后台管理系统新增独立的“集群配置”页面，用于运行期调整平台能力测试的集群策略。页面配置会写入 `cache/runtime-settings.json`，保存后立即生效，不需要重启容器。

当前支持的配置：

- 调度模式：`主节点 + worker`、`仅主节点`、`仅 worker`。
- Worker 节点地址：一行一个地址，支持 `节点名=http://ip:port` 或直接填写 `http://ip:port`。
- 测试并发数：控制平台能力测试同时执行的样本数量，最大 `16`。
- 健康检查超时：后台摘要和集群页探测 worker `/api/health` 的超时时间。
- 远程测试超时：主节点调用 worker 执行单条平台样本测试的超时时间。
- 节点启停：可以在节点状态表中关闭或启用 worker；关闭后的 worker 不参与平台能力测试，主节点固定启用。

说明：

- 该页面控制的是后台“平台能力测试”的调度策略，不替代 Nginx 对外解析接口的负载均衡配置。
- 如果旧版本已有运行时配置文件但没有 `clusterWorkerEndpoints` 字段，系统会继续读取 `CLUSTER_WORKER_ENDPOINTS` 环境变量，避免升级后 worker 丢失。
- 如果在页面中清空 Worker 节点地址并保存，则表示显式关闭后台测试的 worker 调度。

## 风险与约束

- MySQL/Redis 暂时仍是单点，主节点宕机会影响整个服务。
- Worker 访问 MySQL/Redis 依赖局域网稳定性。
- 解析任务依赖第三方平台，失败率和响应时间会受目标平台限制。
- MySQL/Redis 如果为了临时排查绑定到 `0.0.0.0`，必须由服务器防火墙限制来源 IP。默认 Jenkins 方案会绑定到主节点局域网 IP。
- 后台管理、迁移、数据库清理仍只应在主节点执行。

## 后续演进

后续流量继续增长时，可以按以下顺序升级：

1. 增加更多 worker 节点，只扩展解析服务。
2. 为 MySQL 增加独立机器与备份恢复演练。
3. 为 Redis 增加鉴权、持久化备份和 Sentinel。
4. 为 Nginx 增加备用入口或云负载均衡。
5. 把解析任务拆成异步队列，降低长请求对 API worker 的占用。
